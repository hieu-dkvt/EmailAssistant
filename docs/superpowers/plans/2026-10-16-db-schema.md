# DB và các bảng cho bước đồng bộ: kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose up -d` chạy PostgreSQL 16 (PGroonga + pgvector). `alembic upgrade head` tạo `users`, `mail_sources`, `messages`, `message_ownership` có RLS. Có helper `user_session` cho các bước sau.

**Architecture:** Hạ tầng DB nằm ở gốc repo: `docker-compose.yml` và `db/` (Dockerfile, script init tạo role, database, extension). Schema nằm trong `backend/`: model SQLAlchemy 2.0, migration Alembic (0001 tạo bảng, 0002 bật RLS và GRANT) và helper phiên async. Test pytest chạy trên database `mailassist_test` trong container.

**Tech Stack:** Docker Compose, PostgreSQL 16, PGroonga, pgvector, Python 3.12, uv, SQLAlchemy 2.0 (asyncio), psycopg 3, Alembic, pytest, pytest-asyncio, Ruff, pyright.

**Spec:** [docs/superpowers/specs/2026-10-16-db-schema-design.md](../specs/2026-10-16-db-schema-design.md)

- Cổng DB: `127.0.0.1:15432:5432`. Không bind `0.0.0.0`.
- Role: `app_owner` (LOGIN, chủ bảng), `app_api` (LOGIN, NOBYPASSRLS), `app_worker` (LOGIN, BYPASSRLS). Database `mailassist` và `mailassist_test`, đều thuộc `app_owner`, encoding UTF8.
- Mật khẩu dev mặc định (chỉ dùng trên máy dev; `.env` ghi đè): `POSTGRES_PASSWORD=dev-postgres`, `APP_OWNER_PASSWORD=dev-owner`, `APP_API_PASSWORD=dev-api`, `APP_WORKER_PASSWORD=dev-worker`. Claude Code không đọc `.env`.

- [ ] **Step 2: `01-init.sh` và compose**

`01-init.sh` (bash, `set -euo pipefail`) chạy bằng `psql -v ON_ERROR_STOP=1` với user `postgres`:
- tạo 3 role với mật khẩu từ biến môi trường `APP_OWNER_PASSWORD`, `APP_API_PASSWORD`, `APP_WORKER_PASSWORD`;
- `CREATE DATABASE mailassist OWNER app_owner ENCODING 'UTF8'`, tương tự cho `mailassist_test`;

`docker-compose.yml`, service `db`:
- `build: ./db`;
- `ports: ["127.0.0.1:15432:5432"]`;
- `environment` lấy từ biến môi trường kèm mặc định dev (`${APP_OWNER_PASSWORD:-dev-owner}`…);
- volume `pgdata:/var/lib/postgresql/data` và `./db/init:/docker-entrypoint-initdb.d:ro`;
- healthcheck `pg_isready -U postgres`.

`.env.example` ghi các biến trên cùng `DATABASE_URL_OWNER`, `DATABASE_URL_API`, `DATABASE_URL_WORKER`. Script `.sh` phải có xuống dòng LF, không phải CRLF; kiểm tra sau khi ghi.

- [ ] **Step 3: Build và chạy**

Run: `docker compose build db` rồi `docker compose up -d db`, chờ healthy (`docker compose ps`).
Expected: trạng thái `healthy`.

- [ ] **Step 4: Kiểm tra**

Run lần lượt:
- `docker compose port db 5432` → `127.0.0.1:15432`
- `docker compose exec db psql -U postgres -d mailassist -tAc "select extname from pg_extension order by 1"` → `pgroonga`, `plpgsql`, `vector`. Kiểm tra tương tự với `mailassist_test`.
- `docker compose exec db psql -U postgres -tAc "select rolname, rolsuper, rolbypassrls from pg_roles where rolname like 'app_%' order by 1"` → `app_api|f|f`, `app_owner|f|f`, `app_worker|f|t`

**Interfaces:**
- Consumes: bảng của Task 3, fixture `owner_engine`, `api_engine`, `clean`
- Produces (SQL trong `op.execute`):
  - `CREATE FUNCTION app_user_id() RETURNS bigint LANGUAGE sql STABLE AS $$ SELECT nullif(current_setting('app.user_id', true), '')::bigint $$`
  - `ENABLE ROW LEVEL SECURITY` trên `mail_sources`, `message_ownership`, `messages`.
  - Policy:
    - `mail_sources_owner`, `message_ownership_owner`: `USING (user_id = app_user_id()) WITH CHECK (user_id = app_user_id())`
    - `messages_owner_select`: `FOR SELECT USING (EXISTS (SELECT 1 FROM message_ownership mo WHERE mo.message_id = messages.id AND mo.user_id = app_user_id()))`
  - GRANT:
    - `USAGE ON SCHEMA public` cho `app_api`, `app_worker`;
    - `app_api`: `SELECT` trên `users` và `messages`; `SELECT, INSERT, UPDATE, DELETE` trên `mail_sources` và `message_ownership`;
    - `app_worker`: `SELECT, INSERT, UPDATE, DELETE` trên cả 4 bảng.
    - Nếu `INSERT` của `app_api` vào `mail_sources` báo thiếu quyền trên sequence của cột identity thì thêm `GRANT USAGE` trên sequence đó.
  - Downgrade: drop policy, `DISABLE ROW LEVEL SECURITY`, `REVOKE` toàn bộ, drop function.
  - Hàm test `as_user(conn, user_id: int | str | None)`: trong transaction hiện tại gọi `select set_config('app.user_id', :v, true)` (None thì không gọi).
